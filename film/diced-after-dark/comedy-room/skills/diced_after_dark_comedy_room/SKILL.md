# DICED AFTER DARK Comedy Room

Use this skill when the user asks for DICED AFTER DARK writing, review, revision or delivery. Follow the writers room rules in the repository before inventing a new standard. Do not treat this skill as a lock, a pass or a platform clearance.

## Read the base first

- Read the repository directory film/diced-after-dark/comedy-room/ and list every file you actually read.

- Read WRITERS_ROOM_RULES.md and REVIEW_TEMPLATE.md before drafting or scoring anything.

- State clearly when a verbatim script file is missing. Never present a local draft as a verbatim revision of a missing original.

- Keep the five LOCKED character masters and every approved scene and prop unchanged. Never redraw, replace or edit a LOCKED asset.

- Flag every new prop, sign or action as unapproved until it is checked against the LOCKED asset index. Never present a flagged item as approved.

## Build the season in order

- Start from research and record each source with its date, link, visible data and limit. Never claim a hit, a preference or a retention rate you did not verify.

- Write a desire table for each character with what the character wants, what mistake the character will make, what price the character pays and what active action the character takes in the episode.

- Give each episode one absurd decision that upgrades at least twice. Make each reversal come from a character choice, not from a random mistake alone.

- Give each episode at least one fruit or food world visual mechanism that cannot be replaced by a human body. Do not stack cheap puns to meet this test.

- Write 4 episodes with 10 shots each and 6 seconds per shot. Give each shot one main visual action, English dialogue, a Chinese translation, a comedy mechanism, a causal link to the next shot, a required asset and a 6 second timing risk.

- Put every 0 to 2 second hook in the picture at second 0 with the camera already moving. Put at least three recognisable comedy beats in each episode. End each episode with a new consequence, not a spoken summary.

- Keep the format at 9 to 16 vertical, cold realistic light, urban cinematic feeling, no warm fairytale light and no narration. Keep all key text as post production graphics, never as AI generated text in the picture.

## Review with evidence

- Score the same 10 items as the writers room rules, each from 0 to 10, with at least one shot or line as evidence for each item.

- Apply the pass bar exactly as written. The total must reach 8.0 and items 2, 4, 5, 6 and 7 must each reach 8. Any blocking causal gap, LOCKED asset conflict, clear rule violation or unintelligible core shot is a FAIL.

- Record problems as P0 for unshootable, causal collapse or asset conflict, P1 for weak comedy engine and P2 for wording and small fixes. Fix all P0 and P1 items in one pass.

- Label your review SELF-REVIEW when you wrote the draft. Never invent a five person panel, an independent review, a production test or an audience test.

- Mark every untested item as NOT TESTED. This includes voice timing, 9 to 16 crop, small screen text readability, character consistency, sound and platform frame review.

- Keep EP01 shot 9 as Nine thousand, nine hundred ninety-nine to go.

- Keep EP04 shot 10 as PAID HUMILITY CLASS, with Cherry registering the humiliation video income under Basil and Potato smiling frozen.

- Keep the 9,900 disputed coupon holders as an open line that only enters a registration process. Never mark them void or resolved without a new user decision.

- Keep the season length decision open until the user decides between 60 seconds and a 90 second revenue version. Never default one version into a commercial decision.

- Keep music undecided until the user gives a title, a source platform and a licence type. Never share one non platform licensed track across TikTok, YouTube and Facebook.

## Deliver without overwriting

- Save a new draft as a new version. Never overwrite an original, a V2, a V3, a V4 or a LOCKED asset.

- Deliver a full season script, a 40 shot review table, item scores with citations, a change log, an external evidence table, a test list and a version and lock status.

- State the lock status as NOT LOCKED until the user confirms it in clear words. A draft, a review or a delivery report never locks itself.

- For GitHub delivery, upload only files the user approved, to the directory the user approved, and report the commit, the file links and what you did not verify. Never overwrite a file with the same name without stopping and reporting the conflict.

- Never write a secret, a token, a password or a card number into a skill, a script or a delivery file.
